# Hacker news Article analysis system (via LLM called "Research Brief")

## Diagram of the system architecture

Hacker news Front page (Discovery source)
        |
        v
Discovery Layer: Fetch and parse the html of the front page, extract article links and metadata (title, author, points, etc.)
        |
        v
Candidate Filtering -> Keep external HTTP/HTTPS links
        |
        v
Article extraction Layer -> Fetch pages, checking the content type, extract main content, skip failures, stop after 2-3 usable articles
        |
        v
Validate Article records
        |
        v
LLM analysis Layer -> Structured per-article insights (key points, sentiment, etc.) and overall summary + cross-article synthesis
        |
        v
Application Validation -> Exact source IDs, exact titles, no hallucinated content, no inference without data, etc.
        |
        v
Terminal report + Markdown artifact -> Structured report with exact source links, and evidence for each insight, plus a final synthesis section that combines insights across articles.


## Implementation Plan

# Discovery Layer
- Use `requests` to fetch the HTML of the Hacker news front page.
- Use `beautifulsoup4` to parse the HTML and extract article links and metadata (title, author, points, etc.).
- Filter the extracted links to keep only external HTTP/HTTPS links.

# Extraction Layer
- For each candidate article link, use `requests` to fetch the page content.
- Responsible for fetching the HTML content of the hacker news and parse it to extract the metadata about the articles, such as titles, URLS and source IDs

# Validation Layer
- Validate the extracted article records to ensure they have the necessary information (e.g., title, URL, source ID).
- Implement checks to ensure that the extracted data is accurate and complete.

# LLM Analysis Layer
- Use an LLM API client (e.g., `openai`) to analyze the extracted article content.
- For each article, generate structured insights such as key points, sentiment analysis, and other relevant information.
- Generate an overall summary and cross-article synthesis based on the insights from all articles.

# Application Validation
- Implement validation checks to ensure that the insights generated by the LLM are based on the extracted data and do not contain hallucinated content.
- Ensure that all insights are supported by evidence from the articles and that no inference is made without data.

# Presentation Layer
- Format the insights and summaries into a structured report that can be displayed in the terminal.
- Generate a Markdown artifact that includes exact source links, evidence for each insight, and a final synthesis section that combines insights across articles.


## Data contract between layers

Hacker news HTML -> List[HackerNewsArticleMetadata]
External Pages -> List[ArticleContent]
List[ArticleContent] -> ResearchBrief
ResearchBrief + Article set -> Verified ResearchBrief + warnings
verified ResearchBrief -> Terminal report + Markdown artifact
